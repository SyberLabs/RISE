# Design: one colour vocabulary, the engine side (B2a)

Status: Design record, build authorized for PR1. Date: 2026-10-05. For Mateo (ids and contracts) and Seth (the Reader). It builds Q6 of the [Consolidated Reader decisions](2026-10-05-consolidated-reader-decisions.md) and §3 "One colour vocabulary" of the [proposal](../CONSOLIDATED-READER.md). It delivers the first two acceptance lines of FND-008: the theme-to-engine map beside `RISE_CURRENT_THEMES`, and each engine rendering all nine themes. B2b, page chrome and the Settings accent, is the third line and follows as its own record. Ground: `origin/main` = `fcc88280`. Every code fact is `path:line` at that commit; nothing was run or rendered, and anything marked *(inferred)* or *(computed)* was reasoned from the code, not seen. The owner questions are in §8, each with its answer line.

## 1. Decision

**Q6 as recorded** (`docs/product/discussions/2026-10-05-consolidated-reader-decisions.md:14`): "The nine themes are the only colours a reader or a model sees. The Settings accent is removed and page chrome follows the reading's theme; the ambient drone is removed." Builds B2 and D2. The record adds (`:22`): "B2 adds its colour maps beside `RISE_CURRENT_THEMES` and never edits it."

**FND-008** (`docs/product/tasks/FND-008.json:13-17`) has three acceptance lines. B2a delivers the first two:

1. A theme-to-engine map sits beside `RISE_CURRENT_THEMES`, keyed by the same nine ids; `RISE_CURRENT_THEMES` is unchanged and the FND-006 guards stay green.
2. Each engine renders all nine themes.

B2b (the third line: page chrome follows the reading's theme; the Settings accent is removed) is a second PR. B2a leaves it exactly one thing: the accessor `sessionColorThemeId(session)` (§4), and it does not touch the `:root` colour defaults the embed poster reads (`src/live/host/LiveHost.css:122, :153, :159`, per the chrome-accent map §7).

**The one rule.** A reading has one theme, on `session.presentation` (`src/core/models.js:310-313`), accepted only when its colours match (`src/core/session-presentation.js:112-120`). Every engine turns that theme into its own value at the moment it is built. An explicit author value wins; the engine's own "no choice" value takes the theme; with no theme, every engine behaves exactly as today. The "no choice" values are named once and tested once: attractor `'white'` (the compiler fills it for every reading, `src/core/session-compiler.js:264-269`; `normalizeFieldStyle` too, `src/core/visual-style-definitions.js:124`), Klee `'random'` (`:133`), Harmonograph climate `'auto'` (`:147`), plate palette `'auto'` (`:150, :153`).

**What this changes for readers.** Only readings that carry a theme today: Jev and Kev answers, rolls and Today, the two samples, and Composer. Composer renders byte-for-byte as today (its cues already carry explicit rows, `src/core/rise-current.js:217, :237`, and it runs no Gallery engine, `:268`); a test proves it for all nine themes. Library, Keystone, Chapel, Journey, Workshop and Reader-setup readings carry no theme and do not change.

## 2. The map

**Module.** `src/core/theme-engine-map.js`, beside `src/core/rise-current.js`. Not inside it: the Worker imports `rise-current.js` to admit Currents (`worker/mcp-server.mjs`, `worker/mcp-gate0.mjs`; grep) and must not learn engine knowledge.

**Imports, read-only.** `JEV_COLOR_THEMES` (`src/core/jev-color-themes.js:9`) for key order; `RISE_CURRENT_THEMES` (`src/core/rise-current.js:122-132`) for the attractor and Genesis columns **by reference**, so the two tables cannot drift and Composer invariance holds by identity; `validateFlameRecipe` (`src/core/flame-recipe.js:137`) for the one derivation it owns. No visuals import. First load: `rise-current.js` is not in the shell (`src/app.js:13` imports only `session-compiler.js` statically; `rise-current.js` is imported by `src/live/**` and the Worker only, grep), and every importer of the map is a lazy chunk (§4), so `measure:first-load` (`scripts/measure-first-load.mjs:40, :47-58`) should not move. CI is the check.

**Rule for cells.** Engine ids, plus an engine's own dial where the engine has no neutral native (two `sat` values for silver, one for classic). Never a hex colour: colours come from `JEV_PALETTES` through `sessionColorTheme`, as `rise-current.js:118-121` already says.
